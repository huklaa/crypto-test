# Base Builder Attribution Checklist

A lightweight checklist for Base apps that want clean, auditable builder attribution without changing application behavior.

## Before release

- Confirm the app is registered in the current Base builder dashboard.
- Keep the public repository and project metadata consistent.
- Record the production commit SHA used for each release.
- Document which transaction-producing flows belong to the app.
- Keep attribution logic separate from signing keys and secrets.

## ERC-8021 / builder-code readiness

- Follow the current Base documentation for builder-code integration rather than hard-coding assumptions from older examples.
- Add attribution only where it accurately represents transactions generated by the app.
- Test attribution in a non-production environment before release.
- Verify that failed or retried transactions do not create misleading analytics.
- Re-check integration after SDK, wallet, or transaction-pipeline upgrades.

## Measurement

- Track releases and attribution changes in version control.
- Compare dashboard activity with application-side transaction logs.
- Investigate large discrepancies instead of optimizing for a vanity metric.
- Never fabricate users, transactions, volume, or engagement to increase builder metrics.

## Security

- Never commit private keys, seed phrases, API secrets, or wallet credentials.
- Do not request unnecessary wallet permissions for attribution.
- Treat dashboard access and deployment credentials as separate privileges.

## Maintenance

Review this checklist whenever Base changes its builder dashboard, attribution standard, SDK guidance, or transaction format. The official Base documentation should remain the source of truth.
